# M160 code health follow-ups

Tasks found by reviewing upstream changes in `159.0.8154.4..160.0.8184.1` (14562
commits) for regressions, deprecations and code-health migrations that apply to
Brave. Tick items off as they land.

## 1. Regressions

### AI Chat's agent can't navigate to new origins: implicit tool origin grants are off

[acef8e005909](https://chromium.googlesource.com/chromium/src/+/acef8e00590978cd65b351f252a80fe31e552247)
turns `kGlicAllowImplicitToolOriginGrants` off, so a navigate tool request no
longer grants its destination origin, while `kGlicCrossOriginNavigationGating`
stays on (Brave doesn't pin it). A navigation to a new origin then asks the
task's delegate through `ExecutionEngine::SendNavigationConfirmationRequest()`,
which refuses when there is none, and Brave creates its tasks with default
`ActorTaskOptions` (no delegate) and an empty `ActorTaskMetadata()`. Brave's
agent browser tests disable the gating feature, so they don't catch it.
[525a4fd6e071](https://chromium.googlesource.com/chromium/src/+/525a4fd6e071b269d2398fd3374570dc7127182e)
starts removing `ToolRequest::AssociatedOriginGrant()`; upstream's replacement
is an explicit grant (`ActorTaskMetadata` with
`added_writable_mainframe_origins`, or
`ExecutionEngine::AddWritableMainframeOrigins()`) or a delegate answering
`RequestToConfirmNavigation()`, as `TtcActorTaskDelegate` does.

- [x] `browser/ai_chat/content_agent_tool_provider.cc`
      (`CreateTaskWithOptions()` and `PerformActions()`): grant the navigate
      target's origin explicitly, or give the task an `ActorTaskDelegate` that
      confirms non-sensitive new origins
- [x] `browser/ai_chat/content_agent_tool_provider_browsertest.cc:137` and
      `browser/ai_chat/content_agent_tools_browsertest.cc:63`: add a case with
      `kGlicCrossOriginNavigationGating` left on that navigates to a new origin
- [ ] ~~`browser/ai_chat/tools/navigation_tool_unittest.cc:49`: drop the
      `AssociatedOriginGrant()` expectation once upstream removes
      `NavigateToolRequest`'s override~~

      `IsCookieAccessible()` (fixed in
      `[cr160][Net] Honor the partitioned cookies override for ephemeral cookies`)
- [x] `chromium_src/services/network/cookie_settings.cc:55-72`
      (`AnnotateAndMoveUserBlockedEphemeralCookies()`): the same check (fixed in
      the same commit)
- [x] Add a test that the override excludes partitioned cookies, as upstream's

      `BraveCookieSettingsTest` in
      `chromium_src/services/network/brave_cookie_settings_unittest.cc` covers

`` `OnlySigninPromoIfNotSignedIn/*` `` as an instantiation prefix and the suite
`*`, and `_SuiteNamed` then matches every failed test to it. cr160
(160.0.8184.1): all 15 failed tests, Android and Linux, listed the
`IsReplaceSyncPromosWithSignInPromosEnabled()` item and its
`ComputeProfileMenuAvatarButtonPromoInfoParamTest` task as leads, and none named
their actual cause.

- [ ] Don't take a pattern whose suite is only wildcards as a suite pattern
      (read `` `Name/*` `` as a test and its parameters), with a test in
      `autolift_test.py`
