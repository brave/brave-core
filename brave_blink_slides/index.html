Brave on Blink
for iOS

Same Brave iOS app. Chromium's engine underneath.

← → to move · F for fullscreen

Why now

  • Until iOS 17.4, every iOS browser had to be WebKit inside.
  • The EU's Digital Markets Act opened the door to other engines through BrowserEngineKit.
  • Chromium already builds its iOS content layer on Blink behind use_blink=true.
  • So: how much of Brave works if we flip that switch?
One GN flag:
--gn=use_blink:true

What it took

  

    
Startup

      
Upstream dropped Brave's main delegate, so the updater, sync and
        variations switches never applied.

      chromium_src/…/ios_content_main_runner.cc

    
Blocking

      
A URLLoaderFactory wrapper asks adblock-rust before each request.

      BlinkAdBlocker · WillCreateURLLoaderFactory

    
Farbling

      
Settings go to each frame over mojo before commit.

      ShieldsSettingsSender → ShieldsSettingsAgent

  






  
Things that bit us

  

    
No components.
      Lists were requested from Google's updater:
      error-unknownApplication.

    
Farbling silently off.
      Blink ignores settings clients whose HasContentSettingsRules()
      is false.

    
Cold-start race.
      The first request can beat the engine build.
